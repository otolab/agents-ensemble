# ドキュメント方針

> **正本:** 本リポジトリの文書の種類・更新ルール・正本の役割分担。

## 種類と役割

| 種類 | 役割 | 更新 |
|------|------|------|
| **システム文書** (`docs/*.md` の各テーマ) | その時点のシステムのスナップショット | 実装・仕様が変わったら正本を更新 |
| **ADR** (`docs/adr/`) | 自明でない設計判断のレコード（ログ） | `accepted` 後は本文を書き換えない。方針変更は新 ADR + supersede |
| **索引** (`README.md`, `AGENTS.md`, `docs/README.md`) | 読者向けの目次 | リンクと一行説明のみ |
| **作業記録** | Issue（GitHub Issues） | PR / Issue コメント上で追う |
| **作業手順** | Skill または [docs/prompts/](prompts/README.md)（リリース手順含む） | 手順の変更に合わせて更新 |
| **実装予定** | GitHub Issue | システム文書に「未実装」「今後」は書かない |

## システム文書

- 現行の構成・API・挙動の**正本**として書く。
- 実装状況の進捗（「Stage N 完了」「#123 対応済み」など）は置かない。必要なら Issue を参照する。
- 将来の検討メモ・段階導入の議論は、システム文書に残さず Issue に記録する。システムに反映された内容だけ正本へ書く。

## ADR

[adr/README.md](adr/README.md) の不変性ルールに従う。

- 記録対象: 仕様の決定について、自明でない判断を要したもの。
- できること: 被参照の追記、Status の更新（supersede 等）。
- しないこと: `accepted` ADR の Context / Decision / Consequences の書き換え。

## 索引

### ルート `README.md`

人間向けの簡易説明と、詳細ドキュメントへの入口のみ。

### `AGENTS.md`

エージェント・人間共通の索引。レビュー手順・リリース手順などの本文は [docs/prompts/](prompts/README.md) 等へ置き、ここからリンクする。

### `docs/README.md`

文書の正本マップと読者別索引。

## 作業記録と手順

| 置く場所 | 内容の例 |
|----------|----------|
| **Issue** | 受け入れ条件、進捗、検討ログ、スコープ判断 |
| **Skill**（リポジトリ外） | 作業・レビューの実行手順 |
| **docs/prompts/** | 本リポジトリ固有のエージェント手順（PR レビュー、起動プロンプト例、参考フロー） |

## 正本の優先

同じテーマが複数ファイルに触れる場合、[docs/README.md](README.md) の正本マップに従う。判断の**理由**は ADR、**いまの挙動**はシステム文書。
